# 阶段 8：文档与多设备扩展验收

## 目标

补齐仓库长期维护所需的架构、模块所有权、设备扩展、输入更新、CI 构建、部署回滚和 Windows EFI 边界文档，不伪造第二台设备或现场执行结果。

## 约束

- 文档必须以当前仓库实际目录和模块为依据，不引入不存在的主机、UUID、密码或硬件事实。
- 记录阶段 1–7 的自动检查链接、提交和现场验收延期状态；绿色 CI 不等于真实会话验收。
- 按用户指令不执行 `nix fmt`、`nixos-rebuild boot`、`nixos-rebuild switch` 或 EFI 写入。
- 文档阶段不修改运行系统；代码修正回退到阶段 7 已推送提交。

## 范围内需求

- R1：编写架构与模块所有权说明，以及新增设备流程。
- R2：编写输入锁定/更新、静态检查、CI 构建、boot/switch 安全流程、回滚和系统代清理说明。
- R3：记录 Windows 与 NixOS 同 EFI 分区、不同 EFI 分区和未知硬件事实时的人工门禁。
- R4：建立阶段验收矩阵，区分自动检查、现场手动检查、延期和归档状态。
- R5：审查公共模块不泄漏 `thinkbook14`、凭据、硬件 UUID、绝对设备路径或非自由全局开关。

## 验收标准

- [ ] AC1：`docs/architecture.md` 描述目录、数据流、模块所有权和新增主机流程。
- [ ] AC2：`docs/operations.md` 描述输入、CI、构建、部署、回滚、系统代清理和 EFI 边界。
- [ ] AC3：阶段清单和文档包含阶段 1–7 的自动检查/现场验收状态及链接，不把延期写成通过。
- [ ] AC4：静态审查确认公共模块没有主机名、密码、UUID、绝对设备路径或 `allowUnfree = true` 等越界设置。
- [ ] AC5：文档改动通过 `git diff --check`，并在推送后由 GitHub Actions 重新检查 Flake 和主机闭包；按指令跳过 `nix fmt` 和 boot/switch。
- [ ] AC6：推送完成后直接归档阶段 8并完成主任务记录；未执行的现场验收保留为延期状态。
